# 文件 + 密钥版验证记录

仅使用虚构文本和测试密钥。环境：macOS 26.5.1、Google Chrome 152.0.7977.84、Node.js 22.23.1。

## 核心测试：15 项通过

包括 Unicode、前导 U+FEFF、1 MiB 边界、空白保留、错误密钥、逐字节篡改、截断/尾随/超长数据、严格密钥格式、规范 Base64、随机 nonce、与 Node crypto 独立实现双向互操作，以及新二进制文件解析和旧版 HTML 数据导入。

## 浏览器完整流程：通过

- 本地 `file://`，浏览器上下文离线。
- 下载与重新选择密钥；拒绝选择其他密钥冒充刚生成的文件。
- 加密输出为 `.vault`，文件开头为 `PVLT0001`，大小恰为 UTF-8 文本长度 + 36 字节；没有网页封装。
- 输出不含虚构明文或原始密钥；独立 Node crypto 可按公开格式解密。
- 保存校验拒绝截断文件；正常校验清除未修改输入；导出后的新编辑得到保留。
- 在解密区选择 `.vault` 和 `.key`，正确还原原文；错误密钥和被篡改密文均被拒绝。
- HTML 标签形式的原文按普通文本显示；显示、失焦隐藏和立即清除正常。
- 旧版 HTML 加密文件可导入并解密，其脚本未被执行。
- 模拟时钟触发实际 5 分钟清除处理；异步读取完成不会恢复已清除的密钥。
- 桌面、390 像素窄屏及 200% 字体放大无横向溢出；人工查看桌面和解密截图。
- 完整操作没有 HTTP/HTTPS 请求或 JavaScript 页面异常。

## 复查与限制

独立代理对本次文件格式切换、保存校验和异步状态变更进行了针对性代码复查，未发现可操作问题，并验证了实际旧版导出物的兼容性。此复查与功能测试不等同于专业安全审计或密码模块认证。

Windows、Linux、Safari、Firefox、手机系统尚未实测。浏览器不能保证彻底擦除内存、交换文件、剪贴板历史，也不能防护已控制的系统或被替换的工具页面。
